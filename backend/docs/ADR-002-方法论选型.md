# ADR-002：方法论选型 — Goal Workflow + gstack + autoresearch

| 属性 | 说明 |
|------|------|
| 状态 | 已采纳 |
| 日期 | 2026-07-08 |
| 关联 | 需求文档 v4.0；supersede ADR 中 v3.0 方法论部分 |
| 前置 | ADR-001-MVP技术决策.md |

---

## 背景

需求文档 v3.0 采用 OpenSpec + Superpowers + gstack（决策层）三层架构。经评审，该方案存在以下问题：

1. OpenSpec 的 spec.md/proposal.md 体系与团队现有 PRD→开发习惯不匹配
2. Superpowers TDD 强制红绿重构对简单 Bug 修复过重
3. gstack 定位为决策层，与其开源项目中「Review/Test/Ship」质量门禁定位不一致

需重新选型方法论，对齐业界成熟实践。

---

## 决策

采用 **Goal Workflow（流程骨架）+ gstack（质量审查）+ autoresearch（自动化加速）** 三层协作体系。

### 组件选型

| 组件 | 来源 | 本项目角色 | 引入方式 |
|------|------|-----------|---------|
| Goal Workflow | [smallnest/goal-workflow](https://github.com/smallnest/goal-workflow) | 流程骨架：PRD→SPEC→Issues→Goal→Review→Ship | 自研 Python CLI，参考其 Skill 模板 |
| gstack | [garrytan/gstack](https://github.com/garrytan/gstack) | 质量审查：plan-eng-review、review、qa | Phase 1 规则引擎；Phase 2 引入 Skill |
| autoresearch | [karpathy/autoresearch](https://github.com/karpathy/autoresearch) + [uditgoenka/autoresearch](https://github.com/uditgoenka/autoresearch) | 自动化加速：modify→verify→keep/discard | 自研 Python 循环，参考 program.md 模式 |

### 职责边界

```
Goal Workflow  → 定义走哪几步（流程骨架）
gstack         → 定义每步过不过（质量审查）
autoresearch   → 定义怎么快速跑到过线（自动化加速）
Agent Runtime  → 底层执行引擎（已有 Orchestrator + Agents + Tools）
```

### 关键设计决策

| 项 | 决策 | 理由 |
|----|------|------|
| 工作单元 | Issue 卡片（非 OpenSpec tasks.md） | 对齐 Goal Workflow；含 verify_command |
| 验证方式 | 二元命令（exit 0 = 通过） | autoresearch 核心要求；可机械判定 |
| Git 策略 | keep=commit，discard=reset | Karpathy 式 ratchet；失败不污染历史 |
| gstack 定位 | 仅质量审查，非决策层 | 与开源 gstack 一致；PRD 阶段由 Goal Workflow 承担 |
| 快速通道 | `--quick` 跳过 prd/spec | 避免小改动流程过重 |
| merge 权限 | 继承 ADR-001：禁止 auto-merge | 安全优先 |

### 目录结构

```
.goal/          # Goal Workflow 产出
.autoresearch/  # autoresearch 配置与日志
.agent/reviews/ # gstack 审查报告
.agent/         # 已有 Session/RAG/Audit（不变）
```

---

## 后果

**正面：**
- 三层职责清晰，可独立演进
- Issue 卡片 + verify_command 使 autoresearch 循环可机械执行
- gstack 质量门禁与业界实践一致
- 复用已有 Agent Runtime，改动集中在编排层

**负面：**
- 需新建 `.goal/` 模块，Phase 1 工作量增加约 1–2 周
- 三层集成测试复杂度高于 v3.0
- 团队需学习新 CLI 命令体系

**待办：**
- 更新架构设计文档对齐 v4.0
- Phase 1 实现顺序：Goal Workflow 骨架 → autoresearch 循环 → gstack 规则审查 → 串联
