# Mini Todo · 需求规格说明（PRD）

| 项 | 内容 |
|----|------|
| 项目名称 | Mini Todo |
| 版本 | v0.1 |
| 形态 | 单页 Web，必须可打开 `index.html` |
| 用途 | 验证智流 MAWP 完整 Deliver（planner → ship） |
| 本期范围 | F1–F4 必做；F5–F6 有则更好 |

---

## 1. 产品概述

做一个**本地可打开**的待办清单小应用。用户能够添加、完成、删除任务；刷新页面后任务仍然存在（本机存储即可）。

本项目用于跑通交付链路，优先「能打开、能操作、能刷新不丢」，不追求完整产品化。

## 2. 目标用户

个人演示使用者：打开浏览器即可操作，无需注册、无需登录。

## 3. 功能需求

| ID | 功能 | 优先级 | 说明 |
|----|------|--------|------|
| F1 | 添加任务 | P0 | 输入标题后按回车或点击「添加」，新任务出现在列表顶部 |
| F2 | 完成 / 取消完成 | P0 | 勾选切换完成态；完成项使用删除线或灰色样式，可区分 |
| F3 | 删除任务 | P0 | 可删除单条任务，删除后列表立即更新 |
| F4 | 持久化 | P0 | 刷新后列表不丢失；可用 localStorage，或内存 API + 前端缓存 |
| F5 | 空态提示 | P1 | 无任务时显示「还没有待办」 |
| F6 | 未完成计数 | P1 | 展示当前未完成任务条数 |

## 4. 用户故事

1. 作为演示者，我想添加一条「买牛奶」，以便当场展示写入。
2. 作为演示者，我想勾掉已完成项，以便展示完成态变化。
3. 作为演示者，我想删除错误条目，以便展示列表更新。
4. 作为演示者，我想刷新页面后仍看到列表，以便证明不是一次性假数据。

## 5. 界面要点

- 单页布局：标题「Mini Todo」、输入框、添加按钮、任务列表。
- 每条任务：勾选框 + 标题 + 删除按钮。
- 完成项：删除线或灰色文字。
- 空列表：显示「还没有待办」（若实现 F5）。
- 视觉简洁即可，不要求设计系统或组件库。
- 入口必须挂到 `index.html`：浏览器直接打开，或本地静态服务可访问。

## 6. 验收标准

- [ ] 能打开主页，不是空白页或 404。
- [ ] 能添加至少 1 条任务，并立刻出现在列表中。
- [ ] 能将任务标为完成，样式可区分未完成项。
- [ ] 能删除任务，删除后不再出现在列表中。
- [ ] 刷新页面后数据仍在（localStorage 即可）。
- [ ] 无登录、无外部付费 API、无云端账号体系。
- [ ] 交付说明写清如何本地打开（直接打开 html，或一条启动命令）。

## 7. 非功能要求

- 单人、单浏览器即可完成演示。
- 不自动 git push。
- 代码量小，优先可运行，不追求完整框架工程。
- 不依赖需密钥的第三方服务。

## 8. 本期范围

**本期做**

- P0：F1 添加、F2 完成切换、F3 删除、F4 持久化。
- P1（可选）：F5 空态、F6 未完成计数。

**本期不做**

- 账号登录、多端同步、云端数据库。
- 支付、后台管理、权限系统。
- 任务分类、标签、截止日期提醒。
- Docker 上云、CI/CD 正式发布。

## 9. 任务拆解（供 Planner）

| ID | 标题 | 依赖 |
|----|------|------|
| T1 | 实现任务增删、完成切换与持久化 | 无 |
| T2 | 生成可打开的前端页并挂到 `index.html` | T1 |

## 10. 交付说明（Ship 时需写清）

本地打开方式二选一即可：

1. 用浏览器直接打开 `index.html`；或
2. 给出一条本地静态服务命令（例如 `python -m http.server`）。

禁止自动向远程仓库 push。
